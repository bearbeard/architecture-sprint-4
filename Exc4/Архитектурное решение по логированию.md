# Планирование

DEBUG - для тестовых окружений для более детального понимания работы системы при исправлении багов
ERROR - ошибки при исключениях, серверные ошибки при обращении к сторонним сервисам (500 HTTP, RuntimeException, ошибки данных в системе, например некорректный переход по статусам)
INFO - важные информационные сообщения, позволяющие понять ход запросов в системе (изменение статуса заказа, обращение в стороннему API, начало загрузки файла/окончание)
WARN - ошибки при некорректом пользовательскм вводе, клиентские ошибки при обращении к сторонним сервисам

# Мотивация

Это позволит снизить затраты ресурсов на диагностику проблем.
В современном ландшафте IT логирование - это необходимое требование к системе.

# Предлагаемое решение

Для быстрого внедрения логирования можно использовать Graylog.

[решение](jewerly_c4_model.drawio)

К продовым логам должны иметь доступ разработчики, лиды, специалисты поддержки
К остальным логам имеют доступ все.
Чувствительные данные, такие как номера телефонов, данные платёжных карт, адреса электронных почт должны маскироваться.

# Алертинг

Алертинг на логах в данном случае считаю излишним, т.к. уже заложен достаточный мониторинг метриками.
Аномалии эффективнее отслеживать на метриках, т.к. данные размечены.
С ростом сложности системы не исключена вероятность необходимости внедрения подобного алертинга.
