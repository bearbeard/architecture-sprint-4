## Проблемы
- Долгая загрузка начальной страницы MES
- Неинформативность страницы - нужно показывать операторам самые актуальные заказы
для взятия в работу.
- Долгий расчёт стоимости изделия - это напрямую влияет на бизнес, 
т.к. стоимость заказа от одного покупателя может расчитываться много раз перед согласованием и поступлением. работу
- Компоненты дорого масштабировать из-за большого кол-ва контекстов в них


## Инициативы
- Внедрить кэш по модели Refresh-ahead для отображения самых актуальных заказов.   
  - Когда в MES будет добавлен новый заказ он должен пушиться в кэш для приоритетного отображения. 
  - Инвалидация кэша должна происходить при смене статуса заказа
- Переделать отображение заказов на фронте MES, чтобы сразу отображать нужные заказы
- Выделить доменные области приложений Shop API, CRM API, MES для реализации их в отдельных компонентах. 
Масштабировать независимые компоненты
  - Api Gateway - компонент для авторизации и маршрутизации запросов пользователей
    - Декомпозиция Shops API
      - FileUploader - компонент для загрузки файлов с 3ds моделями товара
      - Shops API - компонент для предоставления списка товаров
    - Декомпозиция MES
      - PriceCalculator - компонент, расчитывающий стоимость продукта
      - OrderService - компонент для получения информации о заказах
- Внедрить трассировку запросов для наблюдаемости в расширенной архитектуре
- Внедрить TBD в небольшие компоненты для упрощения жизненного цикла релизов
